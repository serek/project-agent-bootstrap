# Contributing

Open an issue or discussion for substantial changes so scope and compatibility
can be agreed before implementation. Keep changes focused and include the
behavioral evidence appropriate to their risk; consult the project's testing
contract and run the checks available for the change. Report checks that could
not run and why.

Reviewers should assess the submitted change independently against its stated
behavior and project conventions. Maintainers decide acceptance and release.
Package releases follow the versioning policy in `CHANGELOG.md`.

Do not commit credentials, private data, or generated artifacts containing
secrets. Report vulnerabilities through the private process in `SECURITY.md`.
